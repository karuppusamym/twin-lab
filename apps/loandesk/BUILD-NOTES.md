# Build notes: loandesk (brief sha256:455b1e03d138e44c)

## What I built

Server-rendered FastAPI app, one process, one port (8080), no client-side JavaScript.

- `app/main.py`: routes `GET /login`, `POST /login` (303 to `next`, 401 page with `#loginError`),
  `GET /loans?q=`, `GET /loans/{loan_no}`, plus `GET /api/health` and `GET /logout`.
- `app/db.py`, `app/seed.py`, `app/auth.py`: SQLite access, schema creation, synthetic seed, signed session cookie.
- `app/templates/*.html`, `app/static/qtt.css`: markup follows `pages/login.html`, `loans.html`, `loans-item.html`.
- `Dockerfile`, `requirements.txt`, `.dockerignore`. `app.yaml` `run:` set to web/api port 8080, health `/api/health`.

Layout and texts were modelled on the sibling `apps/qtt` app in this repository (same recorded system); the
files were copied and trimmed, not imported.

## Versions pinned

Python 3.13-slim, FastAPI 0.141.1, Starlette 0.50.0, uvicorn 0.35.0, Jinja2 3.1.6, python-multipart 0.0.20
(same as `apps/qtt`). SQLite from the Python standard library. No Bootstrap and no client libraries (see assumptions).

## Assumptions

1. Backend FastAPI (brief: lab default, no evidence). Front end server-rendered Jinja2 templates.
2. Database is SQLite, as the task text says; the brief and `db/schema.sql` say Postgres. The schema is
   applied by rewriting it at start-up (drop `GENERATED BY DEFAULT AS IDENTITY`, `BIGINT` to `INTEGER`,
   `IF NOT EXISTS`). `db/schema.sql` itself is untouched. Tables are only created when missing; each table is
   seeded only when empty. All six schema tables are created, though only users, loans and qc_reviews are read.
3. Bootstrap is "guess" confidence and the snapshots use the app's own `qtt.css`, so Bootstrap is not loaded.
   Bootstrap-like classes in the markup (`btn`, `btn-primary`) come from the snapshots.
4. Brand texts masked in the snapshots were filled from letter counts and the sibling app: "QTT", "Quality
   Tracking Tool", "Work queue", "Sign out", "Back to loan search", and so on. Empty-reviews text is a guess.
5. `/queue` and `/reviews/*` are out of scope, so they answer 404. The recorded snapshots still link to `/queue`
   (`a#appTitle`, `a#navQueue`, which the brief lists as selectors); I kept those links, so they are dead.
   The recording shows a 303 to `/queue` after sign-in; I default the hidden `next` to `/loans` instead.
   `next` is accepted if it is a local path.
6. `GET /logout` is not in the brief's route list but `a#btnLogout` links to it; I implemented it (clear cookie, 303 to `/login`).
7. Unsigned-in requests to `/loans...` get a 303 to `/login?next=...`. Sign-in error text "Invalid user ID or password." is a guess.
8. `/loans` with an empty `q` shows `p#searchHint` only (no count or table); with a `q` it shows `p#loanCount`
   and `table#loanResults`, and `p#noResults` when nothing matches. Search matches loan no or borrower name
   only (not co-borrower); `%` and `_` are taken literally.
9. Unknown loan: HTTP 404 page in the same layout (`#errorMessage`), after sign-in.
10. Review numbers on the loan page are plain text (the review screen is out of scope). The assignee column shows the username.
11. Password hashes: PBKDF2. A stored value that is not in that format is compared as plain text, so a data
    pack with plain demo passwords still works.
12. Seed users (`analyst1`, `analyst2`, `reviewer1`) share the lab credential from `app.yaml` (`lab.credentials`). 60 synthetic loans (more than the 50 limit), 6 reviews.
13. The database file's directory must be writable by the container user (uid 10001, group 0).
14. No `labctl conformance`: `app.yaml` lists no automations under `built_for` that can be run, so there is nothing to run.
    (`built_for` names `loandesk-loan-search`, which is a flow in `flows/qtt-loan-search.yaml`, not an automation.)

## What I could not check

- Real Postgres: not used (task says SQLite).
- Writes by the lab agent to the same SQLite file at the same time as the app: a 30 s busy timeout is set; not exercised.
- Screens against the real recorded pages (only the value-free snapshots exist).

## Things that look wrong in the brief or task

- Brief says database Postgres and `db/schema.sql` is Postgres DDL; the task says SQLite and "create the tables from schema.sql"; the DDL does not run on SQLite unchanged.
- Brief lists `#btnLogin` leading to `/queue` while `/queue` is out of scope.
- The brief says `built_for` automations, "Needed by `loandesk-loan-search`", but that id is a flow, and `flows/qtt-loan-search.yaml` has `app: qtt`.
- Brief "Tables out of scope: queue, loan, check, audit" are not table names in the schema (they are screen names cut short).
- "Docker run ... -v twinlab-loandesk:/data" creates a root-owned volume, which a non-root image cannot write.
- Task step 4 says to run `python -m labctl validate` from the repository root; labctl lives in `lab/labctl` and had to be run there.
